Part 1

Simplicity First — OneR vs ZeroR

🧠 What are these algorithms?

ZeroR (Zero Rules)

The simplest baseline — it always predicts the most common class. No actual learning happens. Use it as a baseline to compare other classifiers.

Example: If 70% of data is "class A", ZeroR always predicts "A" → 70% accuracy.

OneR (One Rule)

Uses one attribute to classify. Tests every attribute, picks the one that gives the best accuracy, and makes a simple rule table from it.

Example: "If outlook = Sunny → No play; If outlook = Overcast → Play..."

  3. Test options: leave as "Use training set" for now → Click Start
  4. In the output panel, look for the "Classifier model" section — it shows you which attribute was chosen and what the rules are

Part 2

Overfitting

🧠 Key Concept: Overfitting

Overfitting happens when a model learns the noise/errors in training data instead of the real underlying pattern → it performs well on training data but poorly on new data.

Solutions: Cross-validation, pruning, simpler models.

▶ Fill the Overfitting Table (4 experiments)

⚠️ IMPORTANT: Use Cross-Validation (10-fold) for all runs in this section!

In the Classify tab, under "Test options" select "Cross-validation" → Folds: 10 → then click Start.

Row 1: weather.numeric — OneR and ZeroR

  1. Open weather.numeric.arff
  2. Run ZeroR with 10-fold CV → note model + accuracy
  3. Run OneR with 10-fold CV → note model + accuracy
  4. Record: "Classifier model: [what attribute/rule] Accuracy: X%"

Row 2: weather.numeric WITHOUT "outlook" attribute

  1. Open weather.numeric.arff in Preprocess
  2. In the attributes list, uncheck "outlook" → Click "Remove" (or use a Remove filter)
  3. Run OneR and ZeroR with 10-fold CV again
  4. Notice how the accuracy changes when the best attribute is removed → this shows overfitting sensitivity

Row 3: diabetes — OneR and ZeroR

  1. Open diabetes.arff
  2. Run ZeroR with 10-fold CV → record
  3. Run OneR (default minBucketSize) with 10-fold CV → record

Row 4: diabetes WITH minBucketSize = 1

  1. Open diabetes.arff
  2. Run OneR → but first click on the algorithm name to open its options
  3. Change minBucketSize from default (6) to 1
  4. Run with 10-fold CV → record model and accuracy
  5. Compare accuracy with Row 3 — minBucketSize=1 may overfit more!
minBucketSize answer: It sets the minimum number of training instances that a bucket (value interval) must contain. Smaller values = more specific rules = risk of overfitting. Larger values = broader rules = less overfitting.

📋 Remark to write:

When minBucketSize is very small (=1), OneR creates very specific rules that fit the training data too closely → the 10-fold CV accuracy may be lower than with default settings, demonstrating overfitting.

Part 3

Using Probabilities — Naïve Bayes

🧠 Key Concept: Naïve Bayes

Naïve Bayes uses probability to classify. For each class, it calculates the probability of the instance belonging to that class given each attribute value, then picks the class with the highest probability.

Key assumption: All attributes are independent of each other (naive assumption). This is usually not true in practice, but it still works well!

▶ Run NaiveBayes on weather.nominal.arff
  1. Open weather.nominal.arff
  2. Classify tab → Choose → bayes → NaiveBayes
  3. Test options: "Use training set" → Click Start
  4. In the output, look at the "Classifier model" block — it shows a probability table for each attribute value given each class

📋 What to fill in the form table:

  • Classifier model column: Copy the probability table from the output (the counts/probabilities for each attribute value under each class)
  • Performance column: Write the "Correctly Classified Instances" percentage shown in the output, e.g., "100% (14/14 instances)"

⚠️ Note: Training set evaluation gives optimistically high accuracy (often 100% on weather). Cross-validation gives more realistic results.

Decision Trees — Entropy, Info Gain & Pruning

▶ 4a: Manual calculation — Build the weather.nominal decision tree

The form asks you to manually calculate Entropy and Information Gain for the weather.nominal dataset, then show which attribute gets selected at each step.

Weather.nominal dataset (14 instances):

Class distribution: 9 "yes" (play), 5 "no" (don't play)

Entropy(S) = -(9/14)log₂(9/14) - (5/14)log₂(5/14) ≈ 0.940

Calculate Info Gain for each attribute:

Outlook (Sunny=5, Overcast=4, Rainy=5):
Sunny: 2yes, 3no → Entropy = 0.971; Overcast: 4yes, 0no → Entropy = 0; Rainy: 3yes, 2no → Entropy = 0.971
Gain(Outlook) = 0.940 - (5/14×0.971 + 4/14×0 + 5/14×0.971) ≈ 0.246
Temperature: Gain ≈ 0.029
Humidity: Gain ≈ 0.151
Windy: Gain ≈ 0.048

→ Outlook has the highest gain (0.246) → selected as root!

📋 How to fill the form table:

Each row = one level of the decision tree. Write the entropy/gain calculations in the first column, and which attribute was selected in the second column. Continue recursively for each branch until pure nodes are reached.

J48 Parameters to know:

  • minNumObj: Minimum number of instances a leaf must have. Higher = simpler tree (less overfitting).
  • confidenceFactor: Controls pruning aggressiveness. Lower value (e.g., 0.1) = more pruning = simpler tree. Default = 0.25.

Part 5

Nearest Neighbor — IBk (K-NN)

🧠 What is K-Nearest Neighbors?

KNN classifies a new instance by finding the K closest training instances (neighbors) and using a majority vote. No model is built — classification happens at prediction time (lazy learning).

  • Small K (e.g., 1): Very sensitive to noise, can overfit
  • Large K (e.g., 20): Smoother decision boundary, may underfit

Write this as your answer to "What is K-NN?"
